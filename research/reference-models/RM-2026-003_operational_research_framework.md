# Reference Model

**Document ID:** RM-2026-003  
**Title:** Operational Research Framework  
**Version:** Official v1.0  
**Status:** Reference Model — Candidate for Repeated Validation  
**Research Program:** RP-2026-001  
**Owner:** Institution Design Studio

## 1. Purpose

Define how Institution Engineering research may operate alongside real product development. This is not a Foundation Theory.

## 2. Core Model

```text
Research Question
    ↓
Hypothesis
    ↓
Architecture Review
    ↓
Implementation or Operational Inspection
    ↓
Operational Evidence
    ↓
Validation
    ↓
Reference Model Revision
    ↓
Operational Improvement
    ↓
New Research Question
```

## 3. Research Objects

| Object | Purpose |
|---|---|
| RQ | Research question |
| H | Testable expectation |
| AR | Architecture baseline |
| OE | Operational facts |
| VAL | Evidence evaluation |
| RM | Current best model |
| FTR | Mature theory registration |
| FP | Adoption proposal |

## 4. Proposed Principles

1. Operational implementation may be a legitimate research activity.
2. Operational evidence shall be capable of refining Reference Models.
3. Evidence supersedes assumptions.
4. Every Foundation concept shall eventually produce operational evidence.
5. Incomplete or contradicting evidence is valid.
6. Product validation and methodology validation remain distinguishable.

## 5. Evidence Maturity

```text
Static Evidence → Controlled Runtime Evidence → Regression Evidence → Repeated Case Evidence → Cross-Platform Evidence
```

## 6. Initial Case

The Duck case showed that repository inspection can change a research plan and that structural evidence must be separated from runtime evidence.

## 7. Limitations

Current support is based on one initial case with incomplete runtime evidence.

## 8. Maturation Path

```text
Multiple Operational Cases → Repeated Validation → RM Revision → Independent Review → Possible FTR → Possible FP
```
