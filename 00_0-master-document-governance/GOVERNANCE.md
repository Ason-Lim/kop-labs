# GOVERNANCE

## 1. Purpose
This document defines how canonical documentation is proposed, reviewed, approved, published, committed, tagged, and archived.

## 2. Lifecycle
Draft → Documentation Review → Architecture Review → Approval → Publication → GitHub Preservation → Archive

## 3. Documentation Review
Authority: 00_0 Master Document Governance

Checks:
- Structure
- Consistency
- Canonical-source integrity
- Traceability
- Document identity
- Documentation quality

## 4. Architecture Review
Authority: 00_1 Master Architecture

Checks:
- Repository responsibility
- Architecture boundaries
- Dependencies
- Layer consistency
- Cross-repository impact

## 5. Approval
Approval requires completed reviews and resolution of blocking comments.

## 6. Mandatory GitHub Preservation
Every approved Starter Kit shall have:
- One commit
- One annotated tag
- One push to the official repository
- One archive snapshot

No subsequent Starter Kit shall begin before the preceding Starter Kit is committed, tagged, pushed, and archived.

## 7. Mandatory Engineering Rules
- One Starter Kit, One Commit
- One Starter Kit, One Tag
- One Starter Kit, One Archive
- Review Before Expansion
- Discovery Notes Before Scope Expansion
- No Next Starter Kit Before GitHub Preservation
